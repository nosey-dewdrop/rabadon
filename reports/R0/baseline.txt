3. S0.2 — the compiler fallback, as it actually stands today
==========================================================================

  PROJECT.md S0.2 offers two remedies: `${CXX:-c++}` in every test script, OR
  `export CXX` in the Makefile. The first was already done — ten scripts under
  native/ carry `CXX="${CXX:-c++}"` with the reason written above the line:

CXX_CPLUSPLUS_FALLBACK_SCRIPTS=10
    command: grep -rl 'CXX:-c++' native/ | wc -l

  and zero scripts anywhere still fall back to a clang-only name:

CXX_CLANG_FALLBACK_SITES=0
    command: grep -rn 'CXX:-clang' --include='*.sh' --include='Makefile' \
                 --include='*.yml' --include='*.py' . | wc -l

  What was left was the Makefile's own default, `CXX ?= clang++`, which on a
  g++-only Linux box names a command that does not exist and kills `make all`
  before a single test runs. R0 changes it to `CXX ?= c++`.

  R0 does NOT `export CXX`, and the second remedy in S0.2 is the wrong one: an
  exported CXX overrides the ten scripts' own fallback, which is the exact
  protection the comment at native/cmdtext_test.sh:31 was written to provide.
  Doing both would undo the first. This is recorded as a challenge to the plan
  in reports/R0/CLAIM.md rather than as a silent fix.

  S0.2's stated proof is "`make test` exits 0 in a container with only g++".
  That container was NOT run. What was run is the shim in section 1, on macOS.

S0_2_PROVEN_ON=darwin-arm64-with-clang-shim
S0_2_PROVEN_ON_LINUX_G_PLUS_PLUS=no

  So S0.2's checkbox in PROJECT.md stays unticked. R0 removed the last reason
  it would fail; it did not produce the evidence the plan asks for.
